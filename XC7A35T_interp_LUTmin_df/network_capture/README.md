# FPGA DAC24 网络抓取说明

本功能在现有 8 位 DAC 截位之前，直接抓取精确的 24 位有符号 `selected_sample`。
监视逻辑不会对插值处理链施加反压。旧抓取位流每帧为 4096 点/16 包；当前任意输入
位流扩展为 16384 点/64 包。两种格式均为每包 256 个样本，上位机严格兼容两者。

## 展示时按这一套顺序操作

推荐直接使用 GUI 新增的 **“▶ 一键正式冲激测量”**。它会自动开始监听、生成
规定的冲激、等待板上工况匹配、上传并等待回传；没有抢操作时机的要求。完整链路如下：

1. 用 **Vivado 2025.2** 下载
   `network_capture/results/implementation/board_network.bit`。这就是本次 Phase 2
   任意输入位流；下载前按 `BUILD_INFO.md` 核对生成时间、大小和 SHA-256。
2. 网线直连板卡与电脑；电脑有线网卡设为 `192.168.1.20/24`，保持自动协商，确认
   Windows 显示 **100 Mb/s**。若 Wi-Fi 也使用 `192.168.1.x`，展示时先关闭 Wi-Fi。
3. 确认防火墙已允许 UDP 4000 入站。在 VS Code “运行和调试”中选择
   “DAC24 板级测量台（GUI）”并按 F5。
4. 点击左侧 **“▶ 一键正式冲激测量”**。程序会自动选择 **16384 点**冲激，且第 0 点
   严格为 `4194304 (2^22)`、其余为零；同时固定为单次播放并要求每包 ACK。
5. 如果最近收到的板上工况已经与目标相同，程序会直接继续；不相同时，界面只提示
   需要按的一个矩阵键，并持续等待。`SW1–SW4` 是 44.1 kHz 的 1x/4x/8x/128x，
   `SW5–SW8` 是 48 kHz 的 1x/4x/8x/128x。按键请稳定按住约 0.2 秒后松开，
   不要快速连点；什么时候按都可以，无需赶时间。
6. 工况匹配后，程序自动执行 BEGIN → WAVE → COMMIT；所有数据报收到板端 OK ACK
   后，自动等待 UDP4000 回传，不需要再点上传按钮。
7. 等待 UDP4000 进度达到 `64/64`。正式页还会自动核对：上传源、匹配 txid、
   txid 已由本 GUI 收到完整 ACK、16384 点、`start_sample_index=0`、
   `capture_status=0` 以及尾 16 点归零；任一条件不满足都只显示“未判定”。
8. 程序自动切换到“正式冲激频响”页并锁定 PASS/FAIL，同时自动归档正式测量证据，
   不需要勾选“完整帧自动保存”或再点“保存当前帧”。除普通帧的 CSV/NPY/预览 PNG 外，
   还会生成 `_formal_impulse.png/.json/.txt`、`_formal_impulse_time.csv`（完整 16384 点
   板端冲激输出）和 `_formal_impulse_frequency.csv`（完整 `NFFT=2^20` 单边频响）。

“波形源 / 上传”页仍保留，供正弦、双音、WAV/CSV 等自定义实验使用；正式冲激展示
不再要求手动在两个页面之间来回操作。

## Phase 2 固定网络配置

- FPGA MAC 地址：`02:35:24:00:00:01`
- FPGA IP 地址：`192.168.1.10`
- FPGA → PC 抓取：广播 MAC/IP，UDP 源/目的端口 `4000`
- PC → FPGA 上传与控制：`192.168.1.10:4001`
- FPGA → PC ACK：回复上传套接字的源 IP/端口
- 链路模式：100BASE-TX（板上绑带电阻只通告 10/100；请在电脑网卡状态中确认实际协商的速率和双工模式）
- 单包数据：32 字节包头，加 256 个 24 位有符号小端序样本
- 单帧数据：旧位流为 16 包/4096 点；新位流为 64 包/16384 点

板端已实现 ARP 应答，因此电脑可直接把 UDP 4001 数据发送到 `192.168.1.10`；
UDP 4000 广播抓取本身仍不依赖 ARP。ACK、ARP 与音频抓取帧共享发送口，按完整帧仲裁，
不会在一个以太网帧中间相互打断。
板上实际焊接的 RTL8211E 绑带配置为 `AN[1:0]=10`，因此 PHY 只通告 10/100，
而不通告 1000BASE-T。请把电脑有线网卡设置为静态地址，例如
`192.168.1.20/24`；保持自动协商开启；在 Windows 防火墙中放行 UDP 4000；
电脑可与开发板直连，也可通过百兆交换机连接。

和“实际收到合法 FPGA 包”，不会把本机监听或 `sendto` 成功冒充板卡确认。安装精简 Qt

```powershell

python .\network_capture\host\gui_app.py
```

也可以在 VS Code “运行和调试”中选择“DAC24 板级测量台（GUI）”。GUI 提供 16/64 包

为 `0 dBr`，其余谱线表示相对该峰值低多少 dB；页面同时保留显示归一化前的原始峰值

### 任意 1x 输入上传（当前交付位流已支持）

当前目录中的 `board_network.bit` 已包含 UDP 4001 上传、ACK、双 bank 16384 点输入
RAM、16384 点回传和输出头中的 `input_transaction_id/capture_status`。如果另行烧录了
历史 4096 点位流，GUI 上传会超时；不能把本机 `sendto` 成功当成波形已经经过 FPGA。

“波形源 / 上传”页支持正弦、双音、冲激、方波、固定 seed 白噪声、CSV/TXT 和 PCM WAV。
输入会量化为有符号 s24，WAV 如有必要会线性重采样；每个事务最多 16384 个 **1x**
44.1/48 kHz 样本。GUI 在发送前归档量化向量和 transaction ID。默认要求每个
BEGIN/WAVE/COMMIT 收到匹配 ACK；选择“无 ACK 开发模式”时只会显示“本机已发送，板端
未确认”，绝不显示成功。

普通波形默认采用“一次确认”方式：先在频率、幅度、样本数等输入框中填写好全部参数，
再点击一次“输入到板卡（自动生成并上传）”。GUI 会自动生成/量化最新波形，并自动执行
完整的 BEGIN → WAVE → COMMIT 与 ACK 检查；不需要先点“生成波形”，也不需要手工操作协议
步骤。若采样率族或输出倍率发生变化，GUI 会自动按新目标重启监听并持续等待，只要求按一次
界面提示的 SW 键，识别到匹配工况后自动继续。收到普通波形的 COMMIT ACK 后，界面会自动
返回“板上测量/时域”页等待新回传。

“参数修改后自动输入到 FPGA”是可选功能，默认关闭；勾选后才会在停止输入约 `0.9 s` 后
自动上传。“仅生成预览”保留为不发送数据的调试功能。正式冲激仍应使用左侧“一键正式冲激
测量”，不走普通波形输入流程。

GUI 对内置生成的正弦、双音、方波和白噪声默认启用“自动防削顶”，即使幅度框填写
`0 dBFS`，实际上传峰值也会自动限制到 `-6.02 dBFS`（半满量程），并在预览详情和事件
日志中显示请求值与实际值。该保护不缩放 CSV/WAV 导入数据，也不改变正式冲激规定的
`A=2^22`。如需专门验证饱和边界，可手动取消该选项，但不建议在现场展示时关闭。

物理采样率和分支仍由板上矩阵键决定，PC 不会暗中改变硬件工况。不过用户不需要记忆
协议里的 family 编码：GUI 会读取最近完整板上帧，匹配时直接继续，不匹配时只显示需要
按的一个键。普通观察默认勾选“自动跟随板上 SW 工况”：例如从 SW6 切到 SW8 后，GUI
检测到合法的 `48 kHz/128x` 帧便自动重启目标过滤，不需要手工停止、修改过滤和重新监听；
正式冲激或正在等待明确上传目标时不会擅自跟随。“一键正式冲激测量”会持续等待，识别
匹配后自动上传且只上传一次。

GUI 的右侧遥测显示最新合法板端数据包的实时工况，即使该帧因不符合当前目标过滤而被
忽略，也不会继续保留旧的 family/mode。实时包只用于显示；程序仍会等目标工况的完整帧
收齐后才上传，避免把按键切换瞬间当作可靠证据。由于回传采用单缓冲并人为设置包间隔，
按键松开后最多约需 `0.7 s` 才能看到下一帧工况，按一次并等待即可，无需连续敲击。
当前发布位流中，上传 RAM 只负责提供 1x 输入样本；上传事务头中的 mode 不再覆盖实体
矩阵按键。因此上传波形播放期间仍可由 SW1～SW8 切换输出倍率。2026-08-14 之前的历史
位流曾锁存提交时倍率，若出现“上传后按 SW8 仍停在 4x”，必须重新下载当前
`board_network.bit`。

为避免 Vivado Hardware Manager 沿用旧工程产物，本机工程默认路径
`XC7A35T_interp.runs/impl_1/board_demo_competition_dac8_top.bit` 已同步为与
`board_network.bit` 相同的 SHA-256；下载时仍建议核对 `BUILD_INFO.md` 中的哈希。
键位为：`SW1–SW4 = 44.1 kHz` 的 `1x/4x/8x/128x`，`SW5–SW8 = 48 kHz`
的 `1x/4x/8x/128x`。

bit-true 参考必须同时匹配采样率族和倍率。标准文件名中的工况会被GUI识别，例如
`rtl_reference_44100_128x.txt` 只能比较 `44.1 kHz/128x`，不能比较 SW8 对应的
`48 kHz/128x`。若参考与板上工况不同，GUI 显示“参考不适用于当前帧·未判定”，不会再
把错误的参考比较显示成红色 FAIL；需要逐位验证时应选择对应工况的参考文件。

### 正式冲激频响门限

只有同时满足以下条件，GUI 的“正式冲激频响”页才允许给出 PASS/FAIL：本 GUI
会话生成的冲激幅度精确为 `2^22`、完整上传事务已收到板端 ACK、回传头声明上传源、
`input_transaction_id` 与已确认事务一致、`capture_status=0`、模式为 4x/8x/128x、
完整回传 16384 点、`start_sample_index=0` 且最后 16 点为零。算法对响应不加窗，使用
`NFFT=2^20`，按 `H(f)=FFT(y)/(A*L)` 归一化；通带为 10 Hz–20 kHz，44.1 kHz
家族阻带从 24.1 kHz 开始，48 kHz 家族从 28 kHz 开始。仅当捕获完整、
`max(|Gpass|) <= 0.05 dB` 且阻带衰减 `>= 70 dB` 时显示绿色 PASS。普通 ROM 帧、
txid 不匹配、4096 点 128x 截断响应或任意上传波形都不会冒充正式冲激结论。

在 Windows 中，将有线网卡设置为静态地址，例如 `192.168.1.20/24`；
在当前防火墙配置文件中允许 UDP 4000 入站；随后明确绑定该网卡：

```powershell
python .\network_capture\host\dac24_capture.py `
  --bind 192.168.1.20 --output .\network_capture\results
```

GUI 的接收套接字监听 `0.0.0.0:4000`，但上传套接字仍由 Windows 路由表决定出口。
直连时请让有线网卡只配置 `192.168.1.20/24`，不填网关和 DNS。如果 Wi-Fi 也处于
`192.168.1.0/24`，应在展示期间关闭 Wi-Fi，或运行下面的命令确认该网段由有线网卡承载；
否则可能出现“广播抓取得到、上传却收不到 ACK”的现象。

```powershell
Get-NetRoute -DestinationPrefix 192.168.1.0/24
```

若要和 RTL 仿真生成的参考数据比较，参考文件应当每行包含一个有符号整数：

```powershell
python .\network_capture\host\dac24_capture.py `
  --reference rtl_expected.txt --output .\network_capture\results
```

最有说服力的板级结果是 `mismatch=0, max_abs_error=0 LSB`，即不一致样本数为 0，
最大绝对误差也为 0 LSB。

每个网络包还包含 `start_sample_index`。它是从对应数据通路复位时刻开始，
在所选 1x/4x/8x/128x 分支内部维护的、从零开始的计数器。上位机利用它，
将抓取帧与连续 RTL 参考数据中的正确区间对齐，而不是错误地把两个文件都从样本 0
开始比较。因此，参考数据必须采用相同的采样率族、模式、ROM/输入激励和复位起点。

不存在适用于所有情况的通用 `rtl_expected.txt`。必须针对准备展示的采样率族和模式，
生成与板上 ROM 完全对应的参考数据。例如，下列命令使用与配置文件相同的模块参数和
复位起点，生成 131072 个连续的 48 kHz 族、8x 模式样本：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File `
  .\network_capture\tools\generate_rtl_reference.ps1 `
  -Family48k 1 -Mode 2 -SampleCount 131072
```

脚本会生成 `network_capture/results/rtl_reference_48000_8x.txt`，可直接传给
`--reference`。模式编号为：0=1x、1=4x、2=8x、3=128x。
若省略 `-SampleCount`，脚本会对 128x 自动生成 524288 点，以覆盖 PHY 启动延迟和
第一帧；对其余模式自动生成 131072 点。不要仅仅因为另一份脉冲、随机数据或其他模式的
数据也是 24 位，就把它作为比较参考。

下面这段仅适用于“板载 ROM 逐位比较（高级/旧流程）”，不适用于推荐的上传冲激正式
测量。若要稳定展示 ROM 的 0 LSB 误差，请先启动电脑接收程序，再下载配置文件或重新给 FPGA 上电，
并在一帧接收完成前保持采样率族和模式不变。所提供的配置文件上电默认为
44.1 kHz/128x，因此第一次测试使用 `rtl_reference_44100_128x.txt` 最简单。
如果板卡已经运行了很久，上位机会自动跳过超出参考向量范围的旧帧，并继续等待你重新下载位流或复位 FPGA。
由于重新下载位流会同时让 PHY 重新协商，链路恢复前的第一帧可能丢失。更稳定的方法是：
历史上也可用 `SW8`、`SW4` 切换数据通路，但 16384 点/64 包抓帧期间会暂停再次采集，
这种方法不能可靠保证抓到索引 0，已经不再作为 GUI 推荐操作。正式通带/阻带测量请直接
使用“一键正式冲激测量”；其 COMMIT 与抓帧重启已经在 RTL 中做了确定性对齐。

若要测试其他模式，应在切换采样率族的同时选择该模式，或者先切换到另一采样率族再切回，
使数据通路在抓取前重新复位。运行过程中只切换模式会有意保留滤波器状态，因此其复位起点
与固定模式的参考仿真不同。自动生成的 128x 向量长度足够覆盖第一帧。如果第一帧不完整，
或者接收程序报告的 `start_sample_index` 超出参考文件范围，请重新启动接收程序并重新下载/
复位 FPGA；也可以明确生成更长的参考向量。不要把下一帧强行与过短的参考文件比较。

## 板级假设与仍需实测的项目

引脚分配来自所提供的 FPGA IO 对照表。场景功能板原理图将 RTL8211E 绑带配置标为
`TX/RX NoDelay`，PHY 复位信号为低有效 `RST_N`。因此，FPGA 使用 MMCM 额外产生一路
25 MHz 时钟，将送出的 TXC 延迟约 2 ns。`mac_rst` 保持低电平 20 ms；复位释放后再等待
30 ms，才开始发送网络包。

在 100 Mb/s 模式下，RGMII 每个 25 MHz 周期传输一个 4 位 MII 半字节，并在 DDR 的
上升沿和下降沿重复同一个半字节。串行发送器有意用两个时钟周期发送一个字节；这里没有使用
1 Gb/s 模式下“上升沿发送低半字节、下降沿发送高半字节”的映射方式。

接收方向同样按固定 100M 语义实现。由于原理图把 PHY 配成 `RX NoDelay`，
`MAC_RXD[3:0]/MAC_RXCTL` 由 5 个 `IOB=TRUE`、无复位的单沿输入寄存器在
`MAC_RXCLK` 下降沿采样，此时距离 PHY 上升沿数据切换约 20 ns，位于数据眼中部；
随后在上升沿域完成半字节拼接、前导码/SFD 搜索、FCS/IP/UDP 校验。该实现不使用 IDDR。

正式采信抓取结果前，请在硬件上确认以下项目：

1. 在电脑网卡状态中确认链路为 **100 Mb/s**，或测得 `MAC_RXCLK = 25 MHz`；只有链路/
   活动指示灯亮，不能证明协商速率正确。
2. 测得 `MAC_TXCLK = 25 MHz`，并确认在 PHY 引脚处，它比 `MAC_TXD/MAC_TXCTL`
   晚约 2 ns。
3. Wireshark 能看到 EtherType `0x0800`、广播目的地址和 UDP 4000。
4. 接收程序完整收到旧位流编号 0 至 15，或新位流编号 0 至 63 的全部网络包，并且没有
   报告内容冲突的重复包或描述信息不一致。
5. RTL 仿真使用同一确定性 ROM 输入，并且与抓取帧比较得到 0 LSB 误差。

网络抓取能够证明 FPGA 实际实现后的 24 位数字节点正确，但它不能测量 AD9708、
模拟滤波器或功率放大器；模拟部分仍应使用示波器或频谱仪作为最终证据。

程序生成的单帧 Hann FFT 相对谱只用于直观展示，不能作为通带纹波 `+-0.05 dB` 或阻带衰减
`>=70 dB` 的正式证明。新位流下只有符合上一节全部条件的 16384 点上传冲激回传才能由
GUI“正式冲激频响”页判定；MATLAB/RTL 长向量验证仍应作为交叉证据保留。
